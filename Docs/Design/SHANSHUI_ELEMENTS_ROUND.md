# shanshui@5 景物系统检查：意象准确与随机性

2026-10-20 起草（Claude）。基线是 `feat/shanshui-guohua`（PR #10，`450de48`）。本轮分支 `feat/shanshui-elements`，叠在它上面。
不考虑兼容：直接改 `shanshui@5`，不开新版本。

用户的验收反馈（秋思样张）："小桥、瘦马、右边的坡岸看上去还是很奇怪"。用户要求对**所有景物**做一轮系统检查，目标有两个：

1. **意象准确**：每个景物一眼能认出来，画法是传统山水画里的画法；诗里写到的东西要画出来，景物之间的关系要对。
2. **随机性**：同一景物换种子，形态要真正不同，不只是抖动几个像素；同一首诗换种子，构图也要明显变化。随机只在"准确"的范围里变。

## 0. 审图工具（已加，先用它看现状）

`ZXArtSceneReviewTests` 新加了两个审图测试，`~/review/round.sh <轮次名>` 会一起出图：

- `elements-01.png` … `elements-08.png`，**景物图谱**：每行一种景物，画 6 个种子；同一行统一缩放，左栏写景物名和缩放倍数。
- `variety-1.png` … `variety-3.png`，**种子谱**：15 类场景，每类 4 个种子的竖幅。

现状样张在 Mac 上：`/Volumes/XiPass/literature/taste/reviews/elements-r0/`。
本轮的验收以这两套图、15 类场景样张和下面第 4 节新加的"组合谱"为准。

图谱有一个缺陷，要先修：月、日、残月、星、雨、雪、瀑布在场景里走的是 `ShanShuiSceneV5` 里的专门画法，图谱现在调的是 `paintingAsset` 的旧兜底，所以和场景不一致。把这些画法提成引擎函数，让场景和图谱都调用它。原则是**图谱上看到的，就是场景里画出来的**。

## 1. 检查结果：意象不准的景物

下表逐项写出 elements-r0 上看到的问题、传统画法和随机维度。"无变化"指 6 个种子画出来完全一样。

### 1.1 人物与动物（用户点名，最优先）

| 景物 | 现在 | 应该是 | 随机维度 |
|---|---|---|---|
| `horse` 瘦马 | 无变化。身体是一整块浓灰椭圆，四条直杆腿，头身比例不对，像桌子或甲虫 | 白描或没骨淡墨，不是实心色块。瘦马要看得出脊背、胯骨、肋下几笔；颈长，向前下垂；头是楔形，有耳。前腿膝向前折，后腿飞节向后折，蹄小。尾下垂，背上可以有鞍或驮包。高度和人相称：马肩高约等于人肩高 | 站立低头、行走（一腿抬起）、低头吃草；有人骑或有人牵；朝向；毛色深浅 |
| `traveler` 点景人物 | 无变化。一个灰锥形加一根杖 | 传统点景人物：头部一点，身体三到五笔衣纹（钉头鼠尾），身长约七个头。按诗意分姿态 | 策杖独行（身体前倾）、拱手立、负担、坐观、戴笠或不戴；朝向；衣纹浓淡 |
| `crow` 昏鸦 | 无变化。孤零零一个 V 字 | 昏鸦要成群，2 到 5 只，大小远近不同；可以栖在老树枝头（"枯藤老树昏鸦"）。飞鸦是浓墨小点加两笔翅，翅形各不相同 | 数量；飞或栖；翅的姿态 |
| `swallow` 燕 | 无变化，和鸦几乎一样 | 剪刀尾、细长翅，常成对出现 | 单只或成对；翅的姿态 |
| `egret` 鹭 | 无变化，可接受 | 现在的画法保留 | 站、单腿立、低头啄、飞 |
| `butterfly` / `dragonfly` | 无变化，可接受 | 小，淡，位置贴着花或荷 | 翅的开合；朝向 |

### 1.2 地形、山石与水

| 景物 | 现在 | 应该是 | 随机维度 |
|---|---|---|---|
| `slope.*` 坡岸（用户点名） | 坡内叠着几层半透明的"肩"，像隔着玻璃看到的影子。皴笔是零散的长线，和形体无关。坡顶是一排浓黑圆点，像洞。陡岸（`cliff`）是一排锯齿，像山脉，不像岸 | 一个坡由前后两三块土石组成，**每块有一条完整的中锋轮廓**（可以断，不能重影）。块与块之间用坡脚线分开。皴笔顺坡势从坡顶往下走：近处成束，密集在轮廓和背光处，受光的坡顶留白。苔点是横点或竖点，三五成簇落在坡顶轮廓上，不是圆黑点。陡岸是几块平顶、立面陡的方折大石（斧劈），不是锯齿 | 块数和前后关系；坡度；平坡（倪瓒折带）、土坡（披麻）、石岸（斧劈）三种画法；苔点簇的位置 |
| `massif.*` 主山 | 窄高的石笋或钟乳石。通体同一种卷曲皴纹，没有山脊和山谷，底座窄 | 主峰带宾峰，有脉络：山脊线分出几道，山谷背光。皴笔顺着脉络走（披麻向下披，卷云在矾头）。山头有矾头（一簇圆石），山脊上点树要疏密有致。高远也要底宽，大约是高的 0.45 倍以上，有肩 | 主峰和宾峰的数目与位置；矾头有无；山脊走向；点树多少 |
| `bridge` 小桥（用户点名） | 无变化。只有一种细弧带拱桥，栏杆细得像铁丝，桥头各压一团圆鼓石块。桥下的"水"是一条亮白带，看上去像路 | 至少三种：（1）单孔石拱桥（水乡），拱下有倒影，合起来近似一个圆；（2）石板平桥，一两块石板架在矮墩上（溪山）；（3）木板小桥，两三块板加两根木桩，栏杆可有可无，最常见。桥头**接进坡岸的轮廓里**，不另外放石块 | 桥型；跨度；拱高；有无栏杆；有无人过桥 |
| `stream` / 河道（桥下的水） | 纸白的带子，两边几块灰石，像路 | 水靠岸来界定：两岸有岸线，坡岸的淡墨贴着岸线。水面留白，加两三道短水纹；近宽远窄，从远处流来，入画有来源。桥下要能看出是水：有拱的倒影，或有水纹穿过桥下 | 走向；宽窄；水纹的多少；有无溪石 |
| `waterfall` 瀑布 | 旧画法，几条竖线 | 两侧是浓墨的崖壁，中间留白就是瀑布，加几条淡竖线；下面有水口和溅雾，接到溪里 | 叠数（一叠、二叠）；宽窄 |
| `rock` / `reef` | 一种圆胖的石块，可接受但单调 | 有棱角的石：三面（石分三面），留出受光面，背光处加皴，石脚点苔 | 大小；块数；卧石或立石 |
| `dunes` | 一摞扁透镜，几何感重 | 几道长弧形的沙脊，一侧受光留白，一侧用干笔淡擦；远处几道淡线 | 脊的数目和走向 |

| 景物 | 现在 | 应该是 | 随机维度 |
|---|---|---|---|
| `house` / `hut` | 无变化，而且 `hut` 和 `house` 画的是同一个东西 | `house`：瓦屋或茅屋，一到三间，可加侧厢或柴门，常用三分之二侧面，能看到山墙。`hut`：小茅屋或草亭，屋顶毛糙，可以只有一间，常半藏在树后 | 间数；正面还是侧面；茅顶还是瓦顶；门窗开合；屋里有没有人 |

| `templeGate` 山门 | 无变化，像普通民居 | 歇山顶，中间开拱门洞，两侧接墙或八字墙，门前有石阶 | 一门或三门；墙的长短 |
| `courtyard` 院墙 | 无变化。一块斜放的板，上面一个月洞门 | 粉墙黛瓦：墙头有瓦顶压檐，可以有漏窗或月洞门。墙要和地面透视一致，是水平延伸的墙，不是斜立的板。树在墙后，露出树冠 | 墙的长短和转折；门窗式样 |

| `cityGate` 城楼 | 旧画法，卡通 | 城墙有垛口，开城门洞，上面是重檐城楼；用水墨简笔，不要描成卡通 | 单檐或重檐；墙的长短 |
| `window` / `curtain` | 旧画法，窗框扭曲 | 轩窗：直棂或冰裂纹窗格。帘：竹帘有横向的系带，可以卷起一半 | 窗格式样；帘卷起多少 |

| `fence` | 可接受 | 现在的画法保留 | 段长；疏密；缺口 |

## 2. 意象准确：诗 → 景物

1. **补词表**（`ZXArtPoetryScene.poetryScene`），至少补这些：
   - 人家、茅屋、茅舍、草堂、村舍、柴门 → `house` 或 `hut`；
   - 老树、古木、古树 → `oldTree`；
   - 流水、春水、溪水 → `stream`；
   - 驴 → `horse` 的驴变体（耳长，身短）；
   - 亭 → `pavilion`；塔 → `pagoda`；舟、船 → `boat`。

   改词表要防误判：比如"月亭"这类词不要误中。要加测试。
2. **选中的景物必须画出来**。场景放不下时，要有明确的退让规则，并在测试里检查。秋思现在漏了"人家"和"老树"。
3. 秋思（天净沙）的标准：
   - 老树上栖昏鸦，枯藤缠树；
   - 小桥跨流水，桥边有人家；
   - 古道上一人牵着或骑着瘦马；
   - 夕阳贴着远山。

## 3. 意象准确：景物之间的关系与比例

1. 关系必须成立：
   - 桥跨在水上，两端接岸；
   - 舟在水上，不在岸上；渔翁在舟上，面向水；泊舟有缆绳系岸；
   - 人在路上或岸上，脚要落地；骑马的人坐在马背上，牵马的人和马之间有缰绳；
   - 炊烟从屋顶升起；
   - 鸦栖在树枝上，或在树附近飞；
   - 藤缠在老树上；
   - 鹭在水边；
   - 荷在水里；蜻蜓立在荷苞上；
   - 屋子半藏在树后，柴门和篱笆连着屋子。
2. 比例按"丈山尺树寸马分人"：
   - 人高约等于门高；
   - 马肩高约等于人肩高；
   - 树高为人高的 3 到 8 倍；
   - 屋檐高约为人高的 1.3 到 1.8 倍；
   - 桥面宽能走一个人，桥跨大约 4 到 8 个人高。

   把这些写成测试里的比例检查（在场景的 element bounds 上量）。

## 4. 新加"组合谱"审图（必须做）

新增 `testGroupReviewSheet`，输出 `groups.png`。每行一个传统组合，按场景里的真实比例画在一段坡岸上，每个组合 4 个种子：

1. 小桥流水人家：桥 + 溪 + 屋 + 树；
2. 古道西风瘦马：路 + 行人 + 马（骑或牵）；
3. 枯藤老树昏鸦：老树 + 藤 + 栖鸦与飞鸦；
4. 渔舟：舟 + 渔翁 + 芦苇 + 水纹；
5. 山居：茅屋 + 柴门篱笆 + 炊烟 + 松；
6. 长亭送别：亭 + 柳 + 两个行人 + 路；
7. 山寺：山门 + 塔 + 竹 + 石阶。

只看单个景物，看不出比例和关系的问题，这张图专门看这两点。

## 5. 随机性

1. **景物级**：第 1 节表里的每个景物都要有"随机维度"那一栏里的变化。验收标准：图谱上同一行的 6 个种子，缩略图大小下能一眼分出至少三种形态，而且每一种都准确。不能用"整体随机缩放、旋转、镜像"凑数，可以镜像，但不能只靠镜像。
2. **构图级**：种子谱里同一类场景的 4 个种子，缩略图大小下要能分出构图差别。可以变的有：
   - 骨架（已有的 corner、oppositeBank、depth，以及高远、深远、平远、边角）；
   - 主体在左还是在右；
   - 主树的数目和树种（主宾）；
   - 次要景物的取舍（比如秋思可以是桥在左屋在右，也可以屋在近桥在远）；
   - 远山有无、远山的层数。

   不能变的有：诗句框避让、整宽地带、推荐页和阅读页的留白规则、诗里写到的景物必须出现。
3. 同一种子必须出同一张图（确定性），现有的确定性测试不能坏。

## 6. 工作方式

### 分阶段，每阶段停下来等验收
按下面顺序做。每个阶段结束时提交、出一轮图，然后**停下来**，在回复里列出改了什么、样张轮次名、还差什么。等 Claude 验收后再做下一阶段。

- **阶段 A**：
  - 第 0 节的图谱修正；
  - 第 4 节的组合谱；
  - 马、人物、鸦和燕、桥、溪和河道、坡岸。这是用户点名的。
- **阶段 B**：建筑与器物（1.3）。
- **阶段 C**：树木与植物（1.4），以及主山（1.2 里的 `massif`）、瀑布、石、沙丘。
- **阶段 D**：
  - 天象（1.5）；
  - 第 2 节的词表与"选中必画"；
  - 第 3 节的比例测试；
  - 第 5 节的构图级随机性。

### 看图、测试、约束
看图、测试、约束三部分，与 `SHANSHUI_GUOHUA_ROUND.md` 第 3 节相同。要点如下：

- 出图：提交后执行 `~/review/round.sh <轮次名>`，轮次名用 `elements-a1`、`elements-a2` 这样的格式。样张留在 Mac 上，用 `~/review/view.sh` 和 `~/review/crop.sh` 看，看完执行 `~/review/view.sh --clean`。**必须看图，不能只读代码。** 每改一个景物，都要在图谱上看 6 个种子。
- 测试：在 Mac 上用 xcodebuild 跑。命令见 `SHANSHUI_GUOHUA_ROUND.md`，再加上 `ZixiaoArtTests/ZXArtGuohuaTests`。App 验收（`HuapingEditingTests`、`HuapingArtTests`）在阶段 D 结束时跑。
- VPS 只有 1G 内存：不要在 VPS 上编译、测试，不要装依赖，也不要再起其他 agent。
