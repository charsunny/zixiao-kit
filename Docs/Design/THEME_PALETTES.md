# 传统色配色身份（2026-10）

2026-10-16 定。内核的身份体系（`ZXIdentity`：配色写在 JSON 里、必须写理由、内核不认识产品）再加六套随包配色，以及给 App 用的主题目录与选择组件。第一个接入方是微诗，见 wish 仓库 `docs/THEME_PALETTES.md`；玄览、子晓以后按需选用。

## 1. 来源与边界

- 参照：[daodaolee/china-color](https://github.com/daodaolee/china-color)（384 色，按二十四节气排）。它**没有开源许可**，数据来自郭浩《中国传统色：故宫里的色彩美学》（中信出版社），色值、编排与部分色名有著作权。**只作灵感，不复制它的数据**：不拷 JSON、不照抄色值、不搬它的节气编排。
- 色名是公有的语词，古诗原文是公版。**每个用到的色名都要在微诗诗库里找到原句**，写进身份的 `rationale`（诗句 + 作者 + 篇名）。找不到原句的色名不用，换名。
- 色值自己调，以界面可读为准（见第 3 节的对比度要求）。

## 3. 派生规则与测试

- **对比度**（随包身份一律测，单测遍历 `ZXBundledIdentity.allCases`）：正文（墨）对纸 ≥ 7:1；次级文字、强调、朱印、五支状态色对纸与 surface ≥ 4.5:1；`accentOn` 对强调 ≥ 4.5:1（深色多半是深字）。现有 `paper-ink-seal`、`monochrome-ink` 同样过这组测试。
- **派生**：surface 浅色比纸亮一档、深色比纸亮一档；border / rule = 墨 12% 叠在纸上；track = 墨 7% 叠在纸上；night = 深色纸再暗一档；secondary 取同族的一支冷 / 暖邻色；状态色（success / warning / danger / info）与该套同族调过，满足上面的对比度。派生出的值写死进 JSON，不在运行时算。
- **`rationale`**：写出意象、色名出处（原句 + 作者 + 篇名）、各槽为什么这样取。
- **高对比度**：系统「增强对比度」打开时，沿用 `ZXColorTokens` 现有的处理；若某套在增强对比度下不达标，在该套 JSON 里补 `highContrast` 值（如需新字段，可选、缺省回落，旧 JSON 不受影响）。

## 4. 内核新增

1. `Resources/identities/` 加六个 JSON，`ZXBundledIdentity` 加六个 case（原始值即文件名）。内置身份 `sealText` 一律留空。
2. **主题目录**：`ZXPaletteCatalog`（名字可调整），列出可选配色：id、显示名、一句意象、浅深色样（纸、墨、强调、朱印），供 App 做选择页。目录只描述配色，不含档位；档位由 App 决定。
3. **套用到产品身份**：`ZXIdentity` 加一个方法，把某套随包配色的 `palette` 套进产品身份，保留产品自己的 `type`、`slots`（如微诗的字体与「微诗」印文），名字与理由合并。
4. **随节气**：`ZXSeasonTint` 的五季对应五套配色，按五行配色：春（木，青）→ 苍筤，夏（火，赤）→ 胭脂，长夏（土，黄）→ 缃叶，秋（金，白）→ 月白，冬（水，玄）→ 黛蓝。提供纯函数「季节 → 配色 id」。选「随节气」时不再叠加季节偏色（`seasonTint` 传 nil），避免偏两次。
5. **选择组件**：`ZXPalettePicker`：色样卡片网格（纸面上写一行字、强调色点、朱印小方），支持选中绑定、「随节气」一项、由 App 传入的上锁判断与点击上锁项的回调；无障碍读出色名与意象；支持动态字体与减弱透明度。
6. **测试**：第 3 节的对比度；每个 JSON 都能解码、六个 case 与文件一一对应；季节映射；套用产品身份后 type / slots 不变。
